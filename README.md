# Splitr 💸

> A modern, real-time expense-sharing and debt-settlement platform inspired by Splitwise. Built with **Next.js 16**, **React 19**, **Convex**, **Clerk**, **Inngest**, and **Google Gemini AI**.

---

## 📌 Overview

**Splitr** is a full-stack, event-driven expense tracking and smart settlement application designed to solve shared financial management for roommates, trips, groups, and friends.

Instead of manual calculations and messy spreadsheets, Splitr provides:
- **Instant Reactive Sync**: Live balance and ledger updates with zero polling via Convex reactive subscriptions.
- **Optimal Debt Simplification**: A graph-theoretic backtracking algorithm (LeetCode 465) that minimizes the total number of transactions needed to settle all group debts.
- **Automated Background Workflows**: Durable cron workflows running on Inngest for daily payment reminders and scheduled email digests via Resend.
- **AI-Powered Spending Analytics**: Monthly spending breakdown and personalized budgeting suggestions generated by Google Gemini 2.5 Flash.

---

## 🚀 Key Features

### 1. Expense Tracking & Flexible Splits
- **1-on-1 & Group Expenses**: Create private pairwise obligations or shared group bills.
- **Three Split Modes**:
  - **Equal Split**: Even division across all selected participants.
  - **Exact Amounts**: Manual division with strict client & server-side validation ensuring the split sum equals the total expense.
  - **Percentage Split**: Weighted division ensuring total percentage equals 100%.
- **Categorization**: Tag expenses across categories (Food & Drink, Groceries, Travel, Entertainment, Utilities, etc.) with intuitive visual icons.

### 2. Smart Debt Simplification Algorithm
- When multiple group members pay for various items, a tangled web of cross-debts is created.
- Splitr implements **Optimal Account Balancing** using Depth-First Search with backtracking:
  1. Computes the net balance for each participant ($B_i = \text{Credited}_i - \text{Debited}_i$).
  2. Partitions users into Creditors ($B_i > 0$) and Debtors ($B_i < 0$).
  3. Uses DFS backtracking with exact-match pruning to find the globally minimal transaction list that completely clears all debts.
  - **Complexity**: $O(N!)$ where $N$ is the number of users with non-zero balance ($\le 10\text{--}15$ in typical group activities).

### 3. Smart Settlement System
- Record payments and repayments between friends or group members.
- Dynamic balance calculation: balances are computed as a ledger of immutable obligations minus recorded settlements, preserving complete financial history.

### 4. Background Automation & Scheduled Reminders
- **Daily Payment Reminders**: An Inngest cron job identifies outstanding debts across all users, constructs styled HTML tables of pending balances, and dispatches automated reminder emails via Resend.
- **Monthly Financial Insights with Gemini**: Analyzes user expenses over the previous 30 days and prompts Gemini 2.5 Flash to generate personalized category breakdowns, unusual spending patterns, and budgeting recommendations delivered straight to the user's inbox.

### 5. Secure Authentication & User Identity
- Integrated with **Clerk Authentication**: Social login, email OTP, and session tokens.
- Secure token verification with Convex backend via JWT issuer validation (`CLERK_JWT_ISSUER_DOMAIN`).

## 💾 Data Model & Invariants

Defined in [`convex/schema.js`](convex/schema.js):

| Table | Description | Key Indexes |
| :--- | :--- | :--- |
| `users` | Authenticated profile information (`name`, `email`, `tokenIdentifier`, `imageUrl`). | `by_token`, `by_email`, `search_name`, `search_email` |
| `groups` | Expense-sharing groups (`name`, `description`, `createdBy`, `members[]`). | Internal primary key lookup |
| `expenses` | Recorded transactions (`amount`, `splits[]`, `splitType`, `date`, `paidByUserId`, `groupId`). | `by_group`, `by_user_and_group`, `by_date` |
| `settlements` | Payments settling obligations (`amount`, `paidByUserId`, `receivedByUserId`, `groupId`). | `by_group`, `by_user_and_group`, `by_receiver_and_group`, `by_date` |

### Core Financial Invariants
1. **Strict Positive Amounts**: Every expense and settlement must have an amount $> 0$.
2. **Exact Split Sums**: $\sum \text{split.amount} = \text{expense.amount}$ (validated on both client and backend).
3. **No Self-Settlement**: A user cannot settle with themselves ($\text{paidByUserId} \ne \text{receivedByUserId}$).
4. **Conservation of Balance**: For any group, the sum of all individual net balances is guaranteed to equal zero: $\sum_{i=1}^{M} \text{NetBalance}_i = 0$.

## ⚡ Getting Started

### Prerequisites
- **Node.js**: v18.18+ or v20+
- **npm** / **yarn** / **pnpm**
- Accounts with **[Clerk](https://clerk.com)**, **[Convex](https://convex.dev)**, **[Inngest](https://inngest.com)**, and **[Resend](https://resend.com)**

### 1. Clone the Repository
```bash
git clone https://github.com/pranav0606881/splitwise.git
cd splitwise
```

### 2. Install Dependencies
```bash
npm install
```

### 3. Configure Environment Variables
Create a `.env.local` file in the root directory:

```env
# Convex
CONVEX_DEPLOYMENT=dev:your-deployment-name
NEXT_PUBLIC_CONVEX_URL=https://your-deployment-name.convex.cloud

# Clerk Authentication
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=pk_test_...
CLERK_SECRET_KEY=sk_test_...
CLERK_JWT_ISSUER_DOMAIN=https://your-clerk-domain.clerk.accounts.dev
NEXT_PUBLIC_CLERK_SIGN_IN_URL=/sign-in
NEXT_PUBLIC_CLERK_SIGN_UP_URL=/sign-up

# Inngest & External APIs
RESEND_API_KEY=re_...
RESEND_FROM_EMAIL="Splitr <onboarding@resend.dev>"
GEMINI_API_KEY=AIzaSy...
```

### 4. Run Convex Development Backend
In a separate terminal, start the Convex reactive dev server:
```bash
npx convex dev
```

### 5. Run Inngest Dev Server (Optional, for Background Jobs)
```bash
npx inngest-cli@latest dev
```

### 6. Start Next.js Development Server
```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) in your browser to start using Splitr.

## 🛡️ Reliability & Engineering Highlights

- **Optimistic UI with Reactive Live Sync**: By relying on Convex's subscription model, when any participant logs an expense or settlement, all connected devices update instantaneously without manual refresh or custom polling logic.
- **Safe External Actions**: Third-party API calls (Gemini AI, Resend) are isolated inside Convex `action`s and Inngest background steps. A failure or timeout in an external API will never rollback or corrupt the core financial database.
- **Idempotent Background Jobs**: Inngest workflows re-verify debt states before dispatching emails, preventing duplicate alerts or reminders for already-settled balances.
